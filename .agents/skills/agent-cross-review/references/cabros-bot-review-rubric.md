# Cabros Bot Cross-Agent Review Rubric

When reviewing pull requests generated by another agent (or human) in the `cabros-bot` repository, evaluate the diff against these specific architectural and operational standards.

---

## 1. Asynchronous Safety & Fail-Open Behavior

- **Never Crash Core Flow**: External service failures (Sentry, Firestore, TradingView MCP, Twelve Data, Telegram, WhatsApp, Discord) must **never** block core alert delivery or crash the Express server.
- **Explicit Deadlines**: Native `fetch` must always use an `AbortController` timeout (e.g. `signal: controller.signal`). No unbounded HTTP requests. Body parsing must be guarded within the same timeout context.
- **Safe Retries**: Only retry idempotent operations or transient rate limits (`429`) with explicit backoff caps and parsed `Retry-After` values (avoid integer truncation on floating-point header values). Never retry terminal 4xx client errors.

---

## 2. Notification & Telegram Formatting

- **MarkdownV2 Escaping**: When composing Telegram messages (`parse_mode: 'MarkdownV2'`), all special characters (`_`, `*`, `[`, `]`, `(`, `)`, `~`, `` ` ``, `>`, `#`, `+`, `-`, `=`, `|`, `{`, `}`, `.`, `!`) must be safely escaped using `src/services/notification/formatters/MarkdownV2Formatter.js` unless intentionally part of Markdown formatting.
- **Fail-Open Channel Fallback**: If one notification channel fails, other requested channels must still be dispatched and telemetry logged.
- **Formatting Invariants**: Ensure symbol formatting, currency rounding (`round10`), and price precision match repository conventions.

---

## 3. Storage & Firestore Persistence

- **Sanitize Undefined Values**: Firestore Admin SDK throws serialization exceptions on `undefined` properties. Always strip or sanitize `undefined` keys before calling `docRef.set()`, `docRef.update()`, `transaction.set()`, or `batch.set()`.
- **Idempotency Claims**: When implementing or reviewing deduplication or idempotency locks, ensure claims have bounded expiration TTLs and are released safely on terminal errors.
- **Type Preservation**: Timestamps, numbers, and nested objects must preserve their Firestore data types across read/write rounds.

---

## 4. Security & Authentication

- **Timing-Safe Key Comparison**: All API key validations (`validateApiKey`) must use `crypto.timingSafeEqual` to avoid timing attacks.
- **Fail-Closed in Production**: In production environments (`NODE_ENV=production`, Render, Vercel, Railway), if `WEBHOOK_API_KEY` is unset or malformed, webhook endpoints must reject requests (`503 WEBHOOK_API_KEY_UNSET` or `401`).
- **No Secret Leaking**: Never log, print, URL-encode, or commit secrets (`BOT_TOKEN`, `WEBHOOK_API_KEY`, `BINANCE_API_SECRET`, Firebase credentials). Sensitive headers must be passed via stdin or protected environment variables.
- **Firebase Admin ID Token Verification**: Browser admin routes using Firebase Auth must verify ID tokens strictly (`verifyIdToken(token, true)`) and check role claims (`admin.viewer` vs `admin.operator`).

---

## 5. Environment & Contract Alignment

- **.env.example Parity**: Every new or changed application-owned environment variable must be documented in `.env.example` with valid defaults and descriptions.
- **Firebase Remote Config & README Parity**: Evaluate all non-secret runtime configuration variables for Remote Config eligibility. Add eligible keys to `RemoteConfigService.PARAMETER_SCHEMA`, `firebase-remote-config-template.json`, and validation tests. Ensure 100% parity with `README.md` documentation tables (exact parameter keys, types, descriptions, and fallback defaults). Secrets and process-startup gates must remain environment-only.
- **OpenAPI 3.1 & Postman Sync**: Every new endpoint or request/response variant must be updated in `src/openapi/openapi.json` and `CabrosBot.postman_collection.json`.
- **Postman Negative Variant Completeness**: Validate that `CabrosBot.postman_collection.json` contains runnable invalid query and body examples (e.g. 400 `INVALID_REQUEST` for invalid limits, windows, malformed timestamps, or reversed ranges) with executable test assertions (`pm.test`), matching API validation logic rather than only testing success cases.
- **Standardized Error Envelopes**: Verify that all error responses return the standardized error envelope format (`{ success: false, error: "<message>", code: "<CODE>", requestId, retryable }` via `src/lib/errorEnvelope.js`).
- **Replay Payload Preservation**: Verify that single and batch `/replay` endpoints and re-drive handlers start from the complete stored raw input payload and overlay routing metadata, preserving all top-level attributes without field cherry-picking, truncation, or schema degradation.
- **Status Endpoint (`/api/status`)**: Expose new feature flags and dependency readiness checks cleanly under `featureFlags` and `dependencies`.

## 6. Agent & Model Attribution Labels

- **Mandatory Agent-Model Labeling**: Every PR created or updated by an AI coding agent must carry an attribution label matching `<agent>-<model>` (e.g. `antigravity-gemini-3.7-flash`, `codex-gpt-5.6-luna`, `github-copilot-minimax-m3:free`, `claude-*`, `opencode-*`).
- **Label Synchronization**: When cross-reviewing a PR, verify that the PR has its proper agent-model attribution label attached so the review pipeline and multi-agent metrics can track agent performance accurately.

---

## 7. Testing & Quality Assurance

- **TDD / Test Coverage**: New endpoints, services, parsers, and bug fixes must have dedicated Jest unit or integration tests in `tests/unit/` or `tests/integration/`.
- **Regression Proof**: Bug fix PRs must include a test reproducing the original bug condition and asserting the fix.
- **Mocking Boundaries**: Mock external networks and APIs (Binance, Twelve Data, TradingView, Telegram, WhatsApp, Sentry, Firestore) in unit tests.
- **Clean Suite**: Ensure `pnpm test` passes cleanly with no flaky test suites or memory leaks.
- **Clean Worktree Invariant**: Tests must not mutate the git working tree (e.g. copying built files over source files). Tests exercising build scripts or asset copiers must write to temporary output directories or assert in memory, leaving `git status --porcelain` clean after the test run.

---

## 8. Review Verdicts

Categorize review findings using clear severity levels:

- 🛑 **Critical (Blocker)**: Security flaws, unhandled server crashes, unescaped MarkdownV2 breaking Telegram alerts, un-sanitized `undefined` crashing Firestore, missing auth checks, broken contracts, missing standardized error envelopes on new endpoints, or dropped fields in replay payloads. Must be resolved before merge.
- ⚠️ **Warning (Risk)**: Missing timeout on external call, missing `.env.example` or Remote Config README parity, missing negative Postman collection variants, tests mutating the git working tree, lack of test coverage for edge cases, or potential performance bottleneck.
- 💡 **Improvement (Non-blocking)**: Code simplification, clearer variable names, helper reuse, or enhanced documentation.
- 🔍 **Style / Nit**: Minor formatting or comment improvements.
